## ADR-01. 서비스별 규칙으로 매뉴얼 선택

| 항목 | 내용 |
|---|---|
| 배경 | 수업의 매뉴얼 6종과 샘플 관측. 원본은 전체 관측에서 문서 하나를 선택 |
| 결정 | 서비스별 CPU·메모리·알림 규칙으로 여러 문서를 고르고 정상·정보 부족 구분 |
| 대안 | 임베딩·벡터 DB RAG, BM25, 모델 기반 분류 |
| 이유 | 작은 문서 집합에서 선택 이유를 재현·설명하기 쉽고 제출 전 기본 동작을 우선 |
| 한계 | 동의어·새 표현·새 장애 유형 대응이 제한적. 규칙 유지 비용 발생 |
| 재검토 | 문서 수·증상 표현이 늘고 고정 평가에서 누락이 반복되면 검색 방식 비교 |

## ADR-02. 코드 기반 구조·근거 검사와 제한된 재작성

| 항목 | 내용 |
|---|---|
| 배경 | 길이·번호 검사는 잘못된 수치도 통과. 반복 실패의 강제 통과 존재 |
| 결정 | 모델은 가설·claims·문서 단계만 JSON으로 작성. 코드는 관측·수치·출처·조건을 검사하고 보고서 표시 |
| 대안 | LLM-as-judge 전체 채점, 자유형 답변을 정규식으로만 검사 |
| 이유 | 서비스·수치·출처는 결정론적으로 대조 가능. 추가 평가 호출 비용과 판단 변동을 줄임 |
| 한계 | 가설의 의미 전체를 판정하지 못함. 형식 제약으로 유용한 답변이 반려될 수 있음 |
| 실패 정책 | 최초 작성 + 재작성 1회. 한도 후 분석·조치 제외, 확인한 근거와 한계 안내 |
| 재검토 | 정답 오차단·의미 오류 표본이 축적되면 사람이 라벨링한 평가와 보조 LLM 판단 비교 |

## ADR-03. SQLite에 최종 보고서·비교 스냅샷 저장

| 항목 | 내용 |
|---|---|
| 배경 | 같은 대화의 결과를 재시작 후 조회하고 과거 비교가 바뀌지 않게 해야 함 |
| 결정 | 메시지·맥락·조사를 같은 로컬 DB 트랜잭션으로 저장. UUID로 조사 구분, comparison도 저장 |
| 대안 | 브라우저에만 저장, 별도 DB 서버, 조회할 때마다 가장 최신 두 기록 비교 |
| 이유 | 기존 저장 구조를 재사용하고 보고서·화면·파일을 같은 데이터로 연결 |
| 한계 | 단일 서버 실습. 인증·다중 서버·부하 확장 미구현. 과거 대화를 원형 관측으로 소급 복원하지 않음 |
| 재검토 | 다중 사용자 공개 서비스나 여러 쓰기 서버가 필요할 때 인증과 공유 DB 설계부터 재검토 |
