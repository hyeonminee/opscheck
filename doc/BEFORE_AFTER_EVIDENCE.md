미제공·미실행·미확인 값은 0으로 채우지 않습니다. 분모가 0인 비율은 미측정입니다. 현재 평가기는 대상·매뉴얼·경로 등의 일부 항목만 계산합니다. 근거 검증·부분 실패 구현 시 오류 차단·오차단·성공 자료 보존 검사를 추가하고 **원본과 개선판에 같은 평가 규칙**을 적용해야 합니다. 저장소가 없는 현재 테스트 대역도 Phase 1의 세션 계약에 맞춰 보완해야 합니다.

잘못된 수치·없는 출처·MCP 부분 실패는 개발자가 고정 입력과 실패 대역으로 재현합니다. 사용자가 수동으로 동일한 상황을 여러 번 만들 필요는 없습니다. 의도적으로 넣은 오류는 **오류 주입 테스트**, 실제 모델이 낸 문제는 **실모델 관찰**로 구분합니다.

## 5. 발표에 사용할 증거

- 검증 흐름: 오류 초안 → 구체적인 검증 실패 사유 → 재작성 → 통과 또는 미통과 종료. 오류 주입인지 실모델 사례인지 표시합니다.
- 부분 실패: payments의 실제 성공 관측·출처와 cache 조회 실패 안내가 함께 있는 화면. 전부 실패 시에는 진단 불가 안내도 확인합니다.
- 가능하면 실제 SSE 요청의 LangSmith 추적을 연결해 보여줍니다. 연결하지 못하면 서버·화면 이벤트로 설명하고 LangSmith 확인 미완료를 밝힙니다. 외부 추적 설정을 위해 개발 시간을 소진하지 않습니다.
- 추적 캡처만으로 가산점을 보장하지 않습니다. 동일 입력·조건의 원시 결과와 건수/비율 표가 전후 비교 근거입니다. [LangSmith 평가 문서](https://docs.langchain.com/langsmith/evaluation-types).
- SQLite는 단일 서버 실습 범위의 선택입니다. 서버별 별도 파일의 대화 공유 문제와 동시 쓰기 제약은 예상 한계로 설명하며, 부하 실험을 하지 않았다면 확인했다고 쓰지 않습니다. 현재 메시지 저장소와 LangGraph 체크포인터를 혼동하지 않습니다. [SQLite 설명](https://www.sqlite.org/whentouse.html), [LangGraph 영속성 설명](https://docs.langchain.com/oss/python/langgraph/persistence).
- RAG·추세 분석·자동 복구 등 이번에 구현하지 않은 기능을 성과로 소개하지 않습니다. 오늘 18시 제출, 16시부터 새 기능 확장 중지·평가 전환 계획을 유지합니다.

## Phase 4 후속 근거

`dev_logs/20261021-phase4/`에 기존 자유형 CPU 1% 사례의 전후 검사, 구조화 오류 검사의 Python 로그, 실제 MCP+fake API/브라우저, 실제 작성 모델의 초기 실패 2회와 지침 보완 후 성공 1회를 보존한다. 자유형 답변은 이제 구조 계약부터 반려하며, 별도 검사는 구조화 claims의 field/value/관측 ID를 변조하여 검증한다. 이를 같은 입력의 종합 사실 정확도 향상 수치로 바꾸지 않는다. 검증기 계약이 달라진 만큼 최종 Phase 7 평가는 표현 방식과 오류 유형·분모를 명시해야 한다. ## Phase 7 최종 평가 — 기존 증거 보존

[최종 보고서](FINAL_REPORT.md)와 `eval/results/phase7-before.json`, `phase7-after.json`·동명 CSV가 최신 비교다. 동일 노드 입력에서 대상 1/7→7/7, 매뉴얼 집합 11/15→15/15, 오류 차단 0/7→7/7·정답 오차단 0/2→0/2, 부분 실패 0/1→1/1을 확인했다. 게이트에 요청 대상을 직접 주입했고 검증기 자유형/JSON 계약 차이를 표시했다. 21개 fake 흐름의 최신 결과 18/21은 확인 분기·없는 문서 기대 불일치 3건을 포함하므로 종합 정확도로 발표하지 않는다. 이전 JSON은 덮어쓰지 않았다.
