# Phase 6 결과 — 이전/현재 비교와 Markdown 다운로드

완료: 2026-10-21 · 다음: **Phase 7 전체 검증·발표 자료 준비**

> **같은 서비스의 직전 성공 관측과 현재 값을 비교하고, 저장된 보고서를 Markdown으로 내려받습니다.** F3·F4를 구현했습니다. 개선 5개·추가 기능 4개의 구현을 마쳤으며 최종 평가·발표 준비는 남아 있습니다.

## 1. 비교하는 항목

| 항목 | 동작 |
|---|---|
| CPU·메모리 | 현재−이전을 퍼센트포인트(%p)로 계산. 90%→70%는 -20%p |
| 서비스 상태 | 두 상태 라벨을 그대로 표시 |
| 알림 | 문자열 집합의 새 알림·해소 알림·유지 알림 |
| 시각 | 이전/현재 조회 시각·간격·이전 조사 ID |
| 한계 | 이전 없음·현재 실패·시각/수치 누락을 비교 불가로 표시 |

비교는 **같은 세션·같은 서비스에서 저장 순서상 가장 최근인 성공 모니터링 관측 1건**을 선택합니다. 보고서가 미통과여도 모니터링이 성공했다면 원형 관측을 사용할 수 있습니다. 다른 서비스·다른 세션·실패/unknown 관측·현재 조사·미래 조사는 이전 관측이 아닙니다.

새 조사는 비교를 함께 스냅샷으로 저장합니다. 이후 조사를 추가해도 과거 비교는 바뀌지 않습니다. 기존 Phase 5 기록은 해당 행 이전만 읽어 비교를 계산하며 원래 JSON은 수정하지 않습니다. 단일 로컬 서버의 동기 저장 흐름을 사용했으며 다중 쓰기 서버의 순서 보장은 실험하지 않았습니다.

### 비교 불가와 시간 해석

- 현재 조회 실패 시 과거 값을 현재 수치로 채우지 않습니다.
- 유효 수치가 없는 필드는 비교 불가이며 다른 정상 필드는 독립적으로 비교합니다. None·문자열·bool·NaN·범위 밖 값은 0으로 채우지 않습니다.
- 관측 시각이 없거나 현재 시각이 이전보다 늦지 않으면 비교를 보류합니다.
- 수업 MCP는 로컬 시각을 offset 없이 만듭니다. 현재 실습의 한국 시간(Asia/Seoul)으로 해석하고 그 사실을 표시합니다. 다른 시간대의 자료를 가져올 때는 명시적 offset이 필요합니다.
- 두 지점의 차이만 보여줍니다. CPU 감소를 복구 완료로 판단하지 않습니다. 알림 문자열 삭제도 실제 장애 해소를 확정하는 의미는 아닙니다.

## 2. Markdown 다운로드

조사 이력에서 기록을 열고 **Markdown 내려받기**를 누릅니다. 파일은 저장된 최종 reply·검증 상태·샘플 표시·comparison으로 만듭니다.

| 파일 내용 | 원본 |
|---|---|
| 관측값·분석·권장 조치·미확인 사항·출처 | 저장된 최종 보고서의 5개 영역 |
| 처리·검증 상태·질문·저장 시각·조사 ID | 같은 조사 기록 |
| 이전/현재 수치·알림·시각·비교 한계 | 같은 비교 스냅샷 |
| 샘플 데이터 안내 | 기록의 is_sample |

미통과 보고서에는 미통과 표시를 유지하고 반려된 분석·조치를 추가하지 않습니다. 파일 생성 시 새 조사·LLM 호출은 없습니다. 같은 저장 기록은 같은 파일 바이트로 내보냅니다.

API: `GET /investigations/{run_id}/report.md?thread_id=...`. 같은 세션의 기록만 반환하며 다른 세션·없는 기록은 404입니다. text/markdown·UTF-8·Content-Disposition attachment를 보내고 프록시도 바이트와 헤더를 그대로 중계합니다.

[실제 브라우저로 내려받아 검증한 예시 파일](../dev_logs/20261021-phase6/browser-downloaded-report.md)

## 3. 화면·API 연결

- 새 진단 직후 채팅 보고서 아래에 비교 결과가 표시됩니다. 첫 조사라면 이전 관측 없음으로 안내합니다.
- `그 서비스 다시 확인해줘`는 새 MCP 관측을 조회한 뒤 비교합니다. 저장된 과거 관측을 현재로 사용하지 않습니다.
- 새로고침 후에는 **조사 이력 상세**에서 저장된 비교와 다운로드를 다시 확인합니다. 기존 채팅 문자열 복원 경로는 유지합니다.
- POST/SSE FinalAnswer에 comparison·comparison_text를 추가했습니다. 최종 5개 영역 report 계약은 유지합니다.
- 조사 상세는 저장된 comparison을 제공합니다. Phase 5 기록에는 필드가 없으므로 해당 행 이전의 자료로 읽기 전용 계산합니다.

## 4. 검증 결과

수정 전 Python 92개 → 수정 후 **104개 모두 통과**, 신규 Phase 6 검사 12개입니다. Node 화면 로직도 통과했습니다.

| 확인 항목 | 결과 |
|---|---|
| 90→70=-20%p | 고정 두 관측으로 통과 |
| 최근 성공 선택 | 저장 순서 사용. 미통과 보고서의 성공 관측 사용, 실패/unknown 제외 |
| 세션·서비스·현재/미래 제외 | 고정 이력으로 통과 |
| 시각·수치 누락과 다중 서비스 일부 실패 | 0 대체 없이 비교 불가 사유 유지 |
| 알림 추가·해소·유지 | 중복을 제거한 문자열 집합으로 통과 |
| 저장 비교 불변성 | 후속 조사 추가·DB 재연결 이후 동일 |
| 저장 보고서와 파일 | 5개 영역·출처·상태·샘플·비교 일치, 반복 다운로드 바이트 동일 |
| 다운로드 프록시 | UTF-8 바이트·Content-Type·Content-Disposition·404/연결 오류 확인 |
| 미통과 파일 | unverified 유지, 반려된 조치 원문 미포함 |
| 이력 조회·다운로드 | 고정 MCP 호출 수 불변 확인 |

실제 MCP stdio + fake 모델에서 첫 진단→후속 새 관측→비교, 미통과 내보내기·다중 서비스·이후 조사 추가를 확인했습니다. 브라우저 링크를 실제 클릭해 Downloads에 파일이 생성됐고 API 응답과 **바이트 단위로 일치**했습니다. 임시 서버 재시작 뒤에도 저장 상세·Markdown 해시가 같았습니다.

검증용 실제 MCP는 샘플 값에 임의 변동을 줍니다. 화면의 수치 변화는 실제 운영 성능·복구 개선의 증거가 아닙니다. 이번 Phase의 유료 호출은 **0회**이며 실제 OpenAI 응답 품질을 다시 측정하지는 않았습니다.

원시 근거: `dev_logs/20261021-phase6/`의 `tests.log`, `ui-tests.log`, `mcp-smoke.json`, `restart-smoke.json`, `browser-phase6.txt/png`, `downloaded-report.md`, `browser-downloaded-report.md`, `review.diff`, `status.json`. 이전 소스·문서는 `before/`에 보존했습니다.
