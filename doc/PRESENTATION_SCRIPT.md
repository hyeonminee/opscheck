## 화면 시연 순서

1. `http://localhost:8600` 접속. 현재 backend·두 모델 표시 확인. OpenAI면 실제 비용 발생.
2. `payments-service 장애 진단해줘` → payments만 조사, cpu-spike 매뉴얼, 5개 영역·검증 상태 확인.
3. `그 서비스 다시 확인해줘` → 새 관측 시각, 이전/현재 수치와 %p 비교 확인.
4. **조사 이력** → 가장 최근 기록 → **Markdown 내려받기**. 저장한 보고서·샘플·검증 상태·비교 확인.
5. 시간이 있으면 **새 대화** → `로그인 응답이 느려요` → 대상 확인 → `auth-service요` → 원래 질문과 연결.
6. `billing-service 응답이 느려요` → 미등록 안내. 다른 서비스 조사로 대체되지 않음.

이전 조사 없는 첫 진단은 비교 불가가 정상이다. 복수 대상 후 “그 서비스”는 모호하므로 다시 확인할 수 있다. 일부 실패를 실제 서비스 이름으로 매번 만들 수는 없다. 오류 주입 증거는 최종 검증 폴더의 별도 fake 화면으로 보여주며 운영 화면에 실패 코드를 넣지 않았다.

## 코드 설명을 위한 최소 확인

- `route_node`: 미등록·미지정·확인 대기·직전 대상 처리.
- `gate_node`: 요청 대상 기준으로 모니터링 작업을 보정.
- `replan_check_node`: 서비스별 필요 문서를 고르고 누락 문서만 한 라운드 조사.
- `validate_draft`: 실제 obs/doc ID와 claims·단계 대조.
- `validate_node`/`finalize_node`: 재작성 1회와 최종 미통과 처리.
- `_save_result`: 메시지·맥락·원형 근거·비교를 같은 조사에 저장.
- `compare_service`: current − previous를 %p로 계산. 시간·수치 불가 사유.
- `export_markdown`: 저장한 결과만 변환하며 새 모델을 호출하지 않음.
