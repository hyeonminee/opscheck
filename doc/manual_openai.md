# 사용자 가이드 — OpenAI API

이 프로그램은 **샘플 모니터링 정보와 대응 매뉴얼로 장애 진단을 연습하는 AI 운영 지원 서비스**입니다. 실제 회사 서버에 접속하거나 로그를 읽고 복구 조치를 실행하지 않습니다.

> 2026-10-20 코드 대조 후 설명을 정정했습니다. 아래 이미지는 제공된 수업 자료이며, 현재 환경에서 새로 측정한 결과가 아닙니다. Phase 0의 실제 실행 화면은 [별도 결과 문서](PHASE0_RESULT.md)에 있습니다. 기존 캡처는 `gpt-4o-mini`·`gpt-4o`를 사용했다고 설명된 수업 참고 자료입니다. 이번 점검에서는 OpenAI를 호출하거나 캡처의 청구 내역을 확인하지 않았습니다. 직접 사용할 때는 본인 키와 결제 설정을 확인해야 하며 실제 API 호출에는 비용이 발생합니다.

실행 순서는 [README](README.md)의 **주요 실행 방법**, 현재 준비 상태는 [개발 전 점검](PREDEVELOPMENT_CHECK.md)을 기준으로 합니다. Phase 0에서 `.venv`·`.env`·설정 템플릿과 기본 모델을 준비했습니다. [실행 결과와 직접 할 일](PHASE0_RESULT.md)을 확인하세요.

## 1. 가벼운 대화

인사·이름 질문은 장애 조사 없이 답합니다. 다만 fake 모드의 키워드 분류는 실제 모델 성능을 나타내지 않습니다.

![사용 예 1 — 가볍게 인사해보기](image_usecase_openai/oa1_greeting.png)

일반 대화도 분류(route)와 답변(chat)으로 모델 요청이 두 번 발생합니다. “한 번 호출·1원 미만”으로 보장할 수 없습니다. 응답의 `cost_usd`는 코드에 설정된 가상 단가를 이용한 추정치로 실제 청구액이 아닙니다. 단계별 모델 분리는 비용을 줄이려는 설계이며 절감액은 별도 측정해야 합니다.

## 2. 장애 증상을 입력해 조사하기

예: “auth-service 응답 지연 장애를 진단해줘.”

![사용 예 2 — 장애 상황을 설명하고 진단 요청하기](image_usecase_openai/oa2_incident.png)

| 단계 | 현재 코드의 실제 동작 |
|---|---|
| 분류·계획 | 일반 대화/장애 요청을 분류하고 조사 작업을 생성 |
| 모니터링 조회 | MCP Tool이 `data/monitoring.json` 샘플을 읽고 CPU·메모리에 임의 변동값을 추가 |
| 추가 조사 | 서비스별 누락 문서만 최대 1라운드 조회. 한도 후에도 부족 사유 유지 |
| 매뉴얼 조회 | Phase 2부터 서비스별 복수 문서 선택. 같은 문서는 한 번 조회하고 관련 서비스·출처·선택 이유 연결 |
| 작성·검증 | 근거 ID가 연결된 JSON 초안 작성. Phase 4 코드가 서비스·측정값·출처·문서 단계·조건 표시를 검사. 최대 2회 실패 시 분석·조치 없이 관측·출처 안내 |

첫 모니터링 호출의 시간 초과는 재시도 학습용으로 **코드가 의도적으로 발생시키는 오류**입니다. 실제 네트워크 장애나 모델 실패를 관측한 결과로 해석하지 않습니다. Phase 4는 구조화된 수치·출처를 대조하지만 원인 가설의 의미 전체를 보장하지 않습니다.

**초안 표시와 검증을 구분해서 읽어주세요.** Phase 4부터 모델 JSON 원문 대신 완성된 가설 문장을 ‘검증 전 초안’으로 전달합니다. 반려된 초안에는 상태와 사유를 남기고 최종 보고서와 구분합니다. 일반 대화에는 검증 배지를 붙이지 않습니다. 최대 2회 작성 후에도 근거 검증 미달이면 가설·조치를 최종 권고로 제공하지 않고 관측·출처·한계를 안내합니다.

OpenAI 어댑터는 제공자 응답을 완성한 뒤 가설 문장을 중계합니다. 제공자 토큰 단위 스트리밍을 새로 구현한 것은 아닙니다.

## 3. 처리 과정 보기

![사용 예 3 — 답변이 만들어지는 과정을 실시간으로 지켜보기](image_usecase_openai/oa3_stream.png)

진행 단계는 SSE로 전달하지만, 현재 OpenAI 어댑터는 완성된 답변 전체를 한 번의 `AnswerToken` 이벤트로 전달합니다. OpenAI 토큰별 실시간 생성 스트리밍이 구현된 것은 아닙니다. 실행 시간은 모델·장치·질문에 따라 달라집니다. 예전 캡처의 수치나 답변은 재현 보장이 아닙니다.

## 4. 대화 기억 확인 — 같은 DB와 대화 ID가 필요

![사용 예 4 — 서버를 껐다 켜도 대화를 기억하는지 확인하기](image_usecase_openai/oa4_restart.png)

SQLite는 메시지를 디스크에 저장합니다. **같은 DB 파일과 같은 `thread_id`를 유지하면** 서버를 다시 만들어도 일반 대화의 이름 기억을 확인할 수 있습니다. 모델이 DB를 직접 읽는 것이 아니라 서버가 이력을 읽어 모델 입력으로 전달합니다.

초기 코드의 DB 삭제·새로고침 ID 변경·v1 SSE 저장 누락·후속 대상 연결 문제는 Phase 1에서 보완했습니다. 같은 DB·브라우저 origin의 대화 ID를 유지하면 메시지와 확인 대기를 복원합니다. 과거 단계 로그·구조화된 조사 보고서 복원은 Phase 5와 구분합니다. [Phase 1 결과](PHASE1_RESULT.md).

Phase 2의 문서 연결·정상/부족 구분은 [별도 결과](PHASE2_RESULT.md)에 정리했습니다. 이름 확인의 일부 명확한 형식은 최근 사용자 기록에서 코드로 답하며 모델 추론을 호출하지 않습니다.

## 5. 브라우저 채팅 화면 사용

![사용 예 5 — 웹 채팅 화면으로 사용하기](image_usecase_openai/oa_web_chat.png)

[README](README.md)의 환경 준비를 마친 뒤 프로젝트 루트에서 실행합니다.

```bash
# 터미널 A — 백엔드 준비 완료까지 대기
bash sh/run_agent_openai.sh
```

```bash
# 터미널 B — A를 켜둔 상태에서 실행
bash sh/run_frontend.sh
```

브라우저에서 `http://localhost:8600`에 접속합니다. 8600의 프록시가 8100 백엔드로 요청을 중계합니다. API와 화면이 같은 처리 로직을 사용하지만, 실제 모델의 답변 문장·수치는 매번 같다고 보장하지 않습니다. Vue CDN 접근이 필요하며 `/health`는 화면의 백엔드·모델 표시에도 사용합니다.

## 6. 자동 평가 화면 — 참고 예시, 현재 배포 기능 아님

![에이전트 답변 품질을 자동으로 감시하기](image_usecase_openai/oa5_eval.png)

이 캡처는 수업의 평가 흐름을 설명하는 참고 자료입니다. 초기 배포에는 평가 코드가 없었고, Phase 0에서 `eval/`에 로컬 고정 평가를 추가했습니다. **LangSmith Dataset 평가 연결·주기 실행·실패 사례 자동 추가는 아직 없습니다.** 이미지의 점수는 이번 프로젝트의 측정 결과가 아닙니다.

LangSmith 추적은 설정하면 사용할 수 있지만, 추적 기록과 Dataset 채점·Feedback 생성은 서로 다른 작업입니다. Phase 0에서 고정 입력·동일 데이터의 비교 장치를 준비했으며 실제 모델 품질·성능 평가는 Phase 7에서 수행합니다. 티켓 검색도 현재 구현된 사용자 기능이 아닙니다.

## Phase 3 적용 사항

모델 호출은 비동기로 실행한다. 전체 요청 120초·모델 호출 45초, MCP 10초·최대 2회, fast 출력 512토큰·quality 1,024토큰·답변 작성 최대 2회다. 시간 초과·잘린 생성·반복 형식 미달은 성공으로 바꾸지 않는다. 독립 조회 실패 시 성공 자료를 보존하고 실패 대상을 표시한다. 모든 모니터링 실패 시 임의 수치 대신 진단 불가를 안내한다. 오류/연결 중단 후 입력을 복구한다. 이 제한으로 모든 실모델 답변이 완성된다고 보장하지 않으며 초기 운영 정책이다. [검증·현재 한계](PHASE3_RESULT.md).


## Phase 4 현재 화면

초안의 가설 문장은 처음부터 ‘검증 전 초안’으로 표시하고, 반려 사유와 재작성 상태를 남깁니다. 모델의 JSON 원문은 화면에 표시하지 않습니다. 통과한 최종 보고서는 관측값·분석·권장 조치·미확인 사항·출처로 구성합니다. 관측값과 출처는 코드로 표시하며 조치는 실제 조회한 매뉴얼 단계와 조건을 유지합니다. 한도 후 실패면 가설·조치를 최종 권고로 제공하지 않습니다. 일반 대화에는 검증 배지가 없습니다. 최신 검증·실모델 범위는 [Phase 4 결과](PHASE4_RESULT.md)를 참고합니다. 기존 이미지는 이전 수업 화면입니다.


## Phase 5 조사 이력

새로고침 후 새 진단을 실행하고 상단 ‘조사 이력’을 연다. 같은 대화의 최근 20건과 저장된 상세 보고서를 확인한다. 수치·출처·검증 상태·샘플 안내를 당시 상태로 보존하며 단순 이력 조회에는 모델/MCP를 호출하지 않는다. 저장 완료 시각은 한국 시간으로 표시한다. 서버 재시작 후 같은 DB·세션에서 복원된다. 과거 채팅은 소급 변환하지 않고 기능 반영 후 조사부터 기록한다. 새 대화는 이전 기록을 지우지 않고 다른 세션으로 전환한다. [검증·범위](PHASE5_RESULT.md).


## Phase 6 상태 비교·다운로드

같은 대화에서 진단 후 ‘그 서비스 다시 확인해줘’로 새 관측을 조사한다. 같은 서비스의 직전 성공 관측과 CPU·메모리 %p·상태·알림 문자열 변화를 비교한다. 이력·시각·수치가 없으면 비교 불가 사유를 표시하고 복구를 확정하지 않는다. 조사 이력의 상세에서 저장된 비교와 ‘Markdown 내려받기’를 확인한다. 내려받기는 저장된 보고서·검증 상태·샘플 안내·비교를 사용하며 새 조사·모델 호출은 없다. [선택 기준·검증·한계](PHASE6_RESULT.md).
